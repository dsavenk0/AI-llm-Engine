# История изменений

Заметные изменения AI-llm-Engine. Даты — 2026 год; релизов с тегами пока нет, всё ниже относится к линии 1.0.
English version: [CHANGELOG.md](CHANGELOG.md).

## Не выпущено — 12 октября

### Изменено — одно приложение
- LLMBar, редактор и голосовой чат — **одно приложение** (`LLMBar.app`, один процесс), разбитое на модули: панель,
  редактор и голосовой чат включаются и выключаются в настройках, ничего не создают до открытия и делят одну тему (тему
  LLMBar). `build-editor.sh` и `build-voice.sh` убраны: `./build-app.sh` собирает всё, включая виджет рабочего
  стола, а `./build-app.sh --install` кладёт приложение в /Applications. Ссылки — `llmbar://…`.
- LLMBar при запуске открывается развёрнутым. Широкий виджет показывает нагрузку GPU и использование RAM по обе
  стороны шара, пока модель включена; точка состояния — закрашенный круг, когда модель включена, и пустое кольцо, когда нет.

### Добавлено
- **API Ollama на том же порту**: `POST /api/chat` и `/api/generate` (потоковый NDJSON или один объект; `options`,
  `tools`, `images`, `think` транслируются), `GET /api/tags`, `POST /api/show`, `GET /api/ps`, `GET /api/version` —
  клиенту Ollama адаптер не нужен. Один путь генерации питает оба формата: OpenAI и Ollama.
- **GGUF-декодер — Gemma 2**: свой MLX-декодер теперь запускает Gemma 2 (tanh soft-cap по attention-скорам и
  выходным логитам, скользящее окно на каждом 2-м слое, sandwich-нормы, GeGLU, tied output), сверено с независимым
  numpy-форвардом с теми же cap.
- **Конвертер GGUF → MLX**: `./llm convert <model.gguf> [out]` экспортирует GGUF как обычную MLX-папку — `config.json`,
  `model.safetensors` в float16 (деквантизация распаковкой самого декодера, имена по формату Hugging Face) и
  `tokenizer.json` из словаря файла — чтобы модель открывалась в mlx-lm без GGUF рядом. Пока llama / Qwen2 / Qwen3.
- **Дирижёр** (опционально, выключен по умолчанию): `./llm conduct` делит задачу по ролям между моделями (heavy /
  code / fast → локальная модель переключается по очереди, или удалённая по API параллельно), с панелью в редакторе.
- **Надёжность**: ответ, оборванный из-за зацикливания, сообщает причину; сторож гасит движок (и llama-server), если
  запустившее приложение упало; нечитаемый документ отменяет отправку и сохраняет текст; чат сохраняется до генерации
  и по мере стрима, есть Retry незавершённого ответа; Voice замолкает, когда вы говорите, и доверяет модели (а не
  только ключевым словам) решать, нужен ли поиск в сети.
- **Редактор помнит размеры**: ширина колонок (чаты / разговор / файлы в чат-режиме, файлы / редактор / структура
  и ассистент в режиме редактора), высота нижней панели и структуры, размер и положение окна сохраняются между
  запусками (разделители — обычные перетаскиваемые ручки, которые запоминают заданное; положение, которое не
  помещается ни на один подключённый экран, игнорируется).
- **Инструменты ассистента через MCP** (отключаемый модуль *Assistant Tools (MCP)*): каталог (context7, Stitch) и
  свои серверы — программа по stdio или streamable-HTTP по URL — подключаются, чтобы ассистент редактора пользовался
  их инструментами на открытом проекте (рабочая папка = корень проекта). Каждый вызов подтверждается, сервер
  контактируется только по *Test* или при вызове, серверы хранятся в workspace `.llm/mcp.json` с доверием по
  содержимому. Это заменяет фичу расширений VS Code (Open VSX): она убрана из приложения и заархивирована в
  `legacy/vscode-extensions/` (в релиз не выходила).
- **Voice**: поиск в интернете — только по чёткому запросу («найди в интернете…») или по явному признаку, что ответ
  меняется (сегодня, погода, цена, счёт…) — не для приветствия и без лишнего вызова модели.
- **Ассистент редактора**: дословное повторение прошлого ответа не показывается (запрос повторяется с пометкой,
  затем без скопированного разговора); модель легче ~1 ГБ получает короткий промпт без инструментов и пометку
  вместо цикла с инструментами, который она не тянет.
- **Ассистент редактора знает, что открыто**: в системной подсказке названы открытый файл и строка курсора, а
  сообщение про «этот код» / «проверь», «исправь», «объясни»… (RU/EN) без вложений отправляет этот файл вместе с
  собой обычной «скрепкой» (небольшой изменяемый файл, только локальная модель) — поэтому «проверь код» относится к
  коду на экране, а не к приветствию.
- **Маршруты говорят, что умеют**: `./llm models` под каждой моделью печатает, какой движок её запускает (engine,
  engine-ptq1, engine-gguf, mlx-lm, llama.cpp) и что он умеет (vision, thinking, tools, ssd-cache, speculation,
  steering); `models --json` содержит `engine` и `features`, а панель показывает их в подсказке модели.
- **Терминал редактора запускает полноэкранные программы** (vim, less, htop, nano): у экранной модели есть
  альтернативный экран, области прокрутки, вставка и удаление строк, сохранённый курсор, прикладные стрелки,
  bracketed paste и рисование рамок DEC; у pty настоящий размер, который следует за панелью (оболочке сообщается
  SIGWINCH), передаются F-клавиши и Page Up/Down. После выхода из программы прокрутка возвращается как была.
- **`./llm inspect [<№|имя|путь>] [--json]`**: что внутри модели, только по заголовкам (27B за мгновение, MLX не
  нужен) — архитектура, слои, головы, словарь, контекст, эксперты, число параметров и бит на вес (PTQ1 / TQ1 считаются
  как 128 весов на 28 байт), типы хранения, крупнейшие группы тензоров со свёрнутыми номерами слоёв и маршрут
  движка (для GGUF — запускает ли его собственный декодер, а если нет, то почему).
- **Агент: параллельный `delegate`**: один вызов может задать одну задачу нескольким исполнителям (`workers`) или
  раздать разные задания разным (`jobs`, до 4); они работают одновременно, одно подтверждение показывает все
  адресаты (с пометкой об удалённых и о CLI-исполнителях, которые могут менять файлы), ответы возвращаются вместе —
  отдельный раздел на исполнителя; отказ одного не скрывает остальных.
- **Виджет**: широкий виджет отмечает избранную модель звёздочкой, а при двух и более избранных нажатие на имя
  переключает на следующую (`./llm fav --next`; работающий движок перезапускается на ней).
- **Редактор: палитра команд** (⇧⌘P, меню View): несколько букв («zi», «term», «newt») находят любую команду меню
  File и View и переключатели модулей — список это сами меню с их горячими клавишами, поэтому лишнего он не предложит.
- **Редактор**: несколько терминалов (вкладки в нижней панели, «+» для ещё одной оболочки, у каждой свой вывод;
  последний закрыть нельзя); большие файлы (больше 2 МБ) открываются как «голова» на 256 КБ только для чтения с
  плашкой, а не отклоняются, и никогда не сохраняются из редактора (сервер тоже откажет, чтобы голова не затёрла
  файл); ошибки типов от `mypy` (Python) и `tsc` (TypeScript) попадают в «Проблемы», если эти инструменты
  установлены — модули, которых проверка одного буфера не видит, ошибками не считаются.
- **LLM Voice: режим диалога, весь разговор, интернет.** После ответа микрофон открывается сам (меню «Режим
  диалога»; заканчивается долгим молчанием, кликом по сфере, пока ничего не сказано, или набранным сообщением).
  Каждый вопрос уходит вместе со всем разговором (новые реплики в пределах бюджета, без «повисшего» ответа), а
  промпт говорит, что уточнения относятся к нему. Вопросы про новости, погоду, цены, счёт или «сегодня» ищутся в
  интернете: модель предлагает запрос (а если маленькая модель молчит — срабатывают ключевые слова на пяти
  языках), `llm web search` берёт результаты DuckDuckGo и верхние страницы, ответ строится по ним; неудачный поиск
  называется прямо, без догадок. Меню: «Искать в интернете, когда нужно» (с Mac уходит только запрос).
- **Больше GGUF на собственном декодере**: Q2_K, Q3_K, IQ4_NL и IQ4_XS (декодируются точно — проверено тензор за
  тензором против деквантизации самого llama.cpp — и затем пере-квантуются по 32 веса в 4 / 5 / 6 / 6 бит, поэтому
  занимают больше памяти, чем в файле), SentencePiece-словари с dummy-пробелом (Llama 2 / Mistral / MiniCPM; id
  токенов совпадают с llama.cpp), MiniCPM с LongRoPE (короткие множители) и её множители. IQ1–IQ3 и MoE-файлы с
  экспертами по отдельности или с общим экспертом по-прежнему идут на llama.cpp.
- **MoE-GGUF на собственном декодере движка** (Mixtral-подобные llama, Qwen3-MoE, Granite-MoE) и плотный Granite:
  эксперты остаются стеком в квантованном виде, токен проходит только свои top-k через `gather_qmm` (при префилле
  токены группируются по эксперту), множители Granite (эмбеддинг / остаток / логиты / внимание) читаются из файла.
  Granite-MoE 1B-A400M совпадает с llama.cpp: те же id токенов, на 32 жадных токена текст идентичен на двух из
  четырёх промптов (в остальных расхождение на почти равных токенах, логвероятности в пределах ~0,3). Файлы с
  экспертами по отдельности или с общим экспертом (Qwen2-MoE, DeepSeek) по-прежнему идут на llama.cpp.
- **Gemma 3 на собственном декодере движка** (GGUF): слои со скользящим окном и своей базой rope, нормы после
  внимания и feed-forward, GeGLU, общий выход с эмбеддингом, линейное масштабирование rope для глобальных слоёв и
  SentencePiece-токенизатор из файла (слияния по score, байтовый запасной путь). Сверено с llama.cpp: одинаковые id
  токенов на английском / русском / CJK / коде / эмодзи, одинаковый жадный текст на 32 токена, в том числе на промпте
  в 1900 токенов со сдвигом окна. llama.cpp остаётся запасным путём для того, что декодер не покрывает.
- **Несколько строк на 1.75-битных моделях** (2–32: проверка черновиков, короткие промпты): слитное ядро
  «декодирование + умножение 8×8» вместо «деквантизация, затем matmul» — 16 строк матрицы 34816×5120 за 2,3 мс
  вместо 8,4 мс (PTQ1_0 и TQ1_G128). Ядро упирается в вычисления (около 6 одно-строчных шагов на 16 строк), поэтому
  спекуляция на таких моделях по умолчанию выключена; `LLM_PTQ1_SPECULATIVE=1` включает её для замеров.
- **LLM Voice**: меню модели есть всегда (со стрелкой), в том числе когда модель не выбрана.
- **Проверка готовности** (`./llm check [--json]`, панель запускает её при старте): Apple Silicon и версия macOS,
  Python, библиотеки движка, сеть (только когда что-то надо скачать), место на диске, модели. Проблемы видны плашкой
  с «Проверить снова»; отсутствие соединения называется прямо, а не обрывает установку. Результат «готово»
  запоминается (requirements + интерпретатор), поэтому рабочая установка стартует без повторного сканирования.
- **Офлайн-сборка**: `./build-app.sh --offline` (и `./build-dmg.sh --offline`) кладёт Python и колёса движка внутрь
  приложения (+~150 МБ); первый запуск не требует сети. Загрузки кешируются в `.build-cache`.
- Неудачная или прерванная первая установка больше не оставляет наполовину созданное окружение, похожее на готовое.
- **Первый запуск на чистом Mac**: если нет Python 3.10+ (или он устарел), менеджер скачивает собственный CPython
  (python-build-standalone, ~35 МБ, проверка SHA-256) в папку данных и затем создаёт окружение движка. Панель пишет
  «ПЕРВЫЙ ЗАПУСК» и показывает ход установки вместо тихого ожидания.
- **История чатов в терминале, общая с редактором**: `llm chat` сохраняет каждый разговор по проектам в том же файле,
  что и редактор; `/history`, `/open <N>`, `/rename <N> <название>`, `/delete <N>` и `/new` показывают, продолжают,
  переименовывают и удаляют чаты, а чат из редактора продолжается в терминале и обратно.
- **История в LLM Voice**: кнопка со стрелкой-часами вверху слева открывает сохранённые разговоры — открыть,
  переименовать, удалить.
- **GGUF на собственном MLX-декодере** (семейства llama / Qwen2 / Qwen3; Q4_0…Q8_0, Q4_K, Q5_K, Q6_K): веса при
  загрузке перепаковываются в квантизацию MLX, токенизатор и шаблон чата берутся из файла. Всё остальное по-прежнему
  идёт через llama.cpp за тем же API.
- **Правки активаций**: `--steer` / `--steer-alpha` и `./llm steer <repo|папка>` применяют направление на выходах
  слоёв, пишущих в residual; базовая модель, для которой сделана правка, скачивается вместе с ней (закреплённая
  ревизия).
- **LLM Voice** — отдельное нативное приложение: говорите или печатайте, прикладывайте файлы и картинки, слушайте
  короткие ответы; обычное окно с кнопками закрыть/свернуть, стекло в стиле LLMBar, своя иконка и виджет рабочего
  стола (`./build-voice.sh --install`), который открывает его сразу в режиме прослушивания.
- **Редактор**: режимы агента (Manual / Edit automatically / Plan / Auto) и Effort, кольцо контекста с Compact,
  переименование и удаление чатов, откат изменений git (по файлу и *Discard all*) с подтверждением, цветовые темы и
  сниппеты Open VSX (по желанию), инструменты поиска в сети и генерации картинок.
- **Избранные модели**: звезда в списке моделей LLMBar, `./llm fav <номер|имя>`, избранные везде идут первыми; меню
  моделей редактора и Voice начинается с них. Кнопка питания на широком виджете включает и выключает модель в
  фоне, а значки голоса / редактора / терминала заранее грузят модель.
- Спекулятивное декодирование по подстрокам промпта для маршрутов mlx-lm и GGUF (при отклонённом черновике кэш
  обрезается назад).
- Тесты: тестер мутаций (`tests/mutate.py`), тесты по эталону для каждого блочного формата GGUF, правила
  префиксного кэша, граничные случаи MCP / парсеров / картинок. Полный набор — больше 700 тестов.

### Изменено
- LLM Voice показывает выбранную модель и её состояние, а пока веса читаются в память — полосу загрузки; слушает
  с момента открытия, модель стартует рядом с микрофоном.
- Картинки, отправленные модели без vision, отбрасываются с одной строкой-заметкой вместо ответа 400.
- Непригодные параметры запроса (`max_tokens`, `temperature`, `stop`…) дают 400 до того, как что-либо запустится.
- `--steer` на бэкенде mlx-lm — ошибка при старте, а не молчаливое игнорирование.
- `build-dmg.sh` пишет установщик в `docs/` — файл, который раздаёт сайт.

### Исправлено
- LLM Voice брал настройки LLMBar (тема, прозрачность, порт, ключ) не из той папки и работал на значениях по умолчанию.
- Редактор: колонка номеров строк больше не закрывает первые символы каждой строки после изменения размера окна, а у
  файла с завершающим переводом строки нет лишнего номера.
- Токен Hugging Face больше не пересылается на CDN, на который перенаправляет загрузка.
- Git: `paths` одной строкой больше не добавляет в индекс весь репозиторий; огромные diff обрезаются на 2 МБ.
- Вывод shell-инструмента ограничен (4 МБ на поток); web-запросы проверяют адрес узла после соединения.
- Клиент MCP: мусор между сообщениями, повторяющийся курсор, инструменты без имени, огромные результаты, упавшие
  серверы.
- Остановка внутри принятого спекулятивного черновика оставляла кэш длиннее поданных токенов.
- Генерация картинок: промпт, начинающийся с `--`, больше не читается как опция.

## 11 октября

### Добавлено
- **LLM Editor** — нативное Swift-приложение (по требованию): чат-ориентированный и классический вид, агент,
  который спрашивает перед правкой, git и GitHub, проблемы, терминал, предпросмотр, диктовка, темы, источник модели
  (другой OpenAI-совместимый сервер), модуль расширений.
- **Маршруты 1.75 бит** на одном Metal-ядре: PTQ1_0, TQ1_G128, JANG packed (экспериментально).
- **Необязательный бэкенд mlx-lm** для архитектур, которых нет в нативном движке, с маршрутизацией
  native / ptq1 / mlxlm.
- **Harness агента**: память проекта и автосжатие контекста, карта проекта и заметки сессии, поиск и чтение страниц,
  клиент MCP (stdio + streamable HTTP, пресеты Context7 и Stitch), `/fix-tests`, передача задач через `/workers`.
- **Бенчмарки**: 14 наборов с доверительными интервалами (GSM8K, MMLU, MMLU-Pro, ARC, HellaSwag, TruthfulQA,
  WinoGrande, KMMLU, C-Eval, MathQA, BBQ, SafetyBench, HumanEval, MBPP); код выполняется в песочнице.
- **Необязательная генерация картинок** через mflux (`./llm setup --images`, `/v1/images/generations`).
- Подключаемые парсеры рассуждений и вызовов инструментов с ручным переопределением; GGUF в папках, хранилища LM
  Studio и Ollama через llama.cpp; ModelScope как второй источник моделей; пауза и продолжение загрузок.
- LLMBar: маршруты и причины, настройки конкретной модели, удаление, Liquid Glass, прогресс чтения промпта, настройки.

### Изменено
- Любая MLX-квантизация загружается по формам тензоров; умолчание рассуждений берётся из шаблона модели.
- Префиксный кэш на SSD пишется только при сне и остановке; бюджет может быть `auto`.

### Исправлено
- Устаревшие pid-файлы, зависшие порты, таймауты команд; стоп-строки вырезаются из ответа; `/health` отвечает во
  сне; зацикленные ответы останавливаются (`repetition_penalty`); неполный файл не остаётся под итоговым именем.
